9. Construire le driver UNIVERSEL (Apple Silicon arm64 + Intel x86_64) pour MariaDB ou MySQL 8.0 sous macOS - build universal MySQL/MariaDB driver QT6 macOS

L'intérêt d'un driver UNIVERSEL : une seule et même application Rufus.app tourne aussi bien sur les Mac Apple Silicon (M1, M2, M3...) que sur les anciens Mac Intel. C'est ce qui est livré dans les paquets officiels de Rufus.

ATTENTION, le point qui surprend tout le monde : un driver universel ne sert à RIEN s'il se lie à une lib client qui ne l'est pas. Le driver (libqsqlmysql.dylib) n'est qu'un pont vers la lib client MariaDB/MySQL (libmariadb.dylib ou libmysqlclient.dylib). Si cette lib client n'existe qu'en arm64, la tranche Intel du driver n'aura rien à appeler. Donc, pour faire de l'universel, il faut d'abord se fabriquer une lib client universelle. C'est l'étape E ci-dessous, et c'est la plus pénible.

(Si vous ne construisez Rufus que pour VOTRE propre Mac, l'universel est inutile : suivez plutôt la page « driver pour macOS Silicon » ou « driver pour macOS Intel x64 » selon votre processeur, c'est beaucoup plus court.)

À FAIRE de préférence sur un Mac Apple Silicon : c'est là que tout se fait simplement. On PEUT aussi produire l'universel depuis un Mac Intel x64, mais c'est nettement plus compliqué (la fabrication de la lib client universelle à l'étape E ne marche pas pareil). Cela dit, le programmeur qui s'entête encore à coder sur un x64 de six ans n'est sans doute pas en train de chercher à livrer un driver universel...

A - La lib client
Les libs compatibles Apple Silicon (arm64) ne sont fournies qu'à partir des versions 8.0.26 de MySQL. Il faut donc impérativement utiliser une de ces versions (ou MariaDB, qui est arm64 depuis longtemps) pour pouvoir compiler le driver sur un Mac arm64.
Se référer à la page www.geeksforgeeks.org/how-to-install-mysql-on-macos/ pour la procédure d'installation.
La configuration du serveur sera identique à celle décrite dans la page du site rufusvision pour la configuration d'un serveur MySQL 5.7 -> Installation du serveur MySQL sous macOS.

B - Installer Qt 6
Installer Qt 6.3 ou supérieur et les SOURCES du logiciel par le biais du logiciel d'installation de Qt, MaintenanceTool. Les sources vont permettre de compiler le driver. Donc, modifiez ou faites une installation neuve en cochant la case « Sources » du logiciel d'installation, comme indiqué dans la capture d'écran ci-contre.
Installer aussi QtCreator, CMake et Ninja en cochant les cases correspondantes (mais elles le sont normalement par défaut).
Installer aussi les librairies additionnelles QtPdf version Desktop, QtMultimedia et QtSerialPort, indispensables au fonctionnement de Rufus.

On est loin d'avoir fini...

C - Télécharger Xcode sur l'App Store et l'installer. (C'est lui qui apporte clang et l'outil lipo, indispensable à l'universel.)

D - Indiquer au système le chemin vers les outils dont il aura besoin pour compiler le driver.
On ajoute les dossiers contenant qt-cmake, cmake et ninja à la variable PATH, en entrant dans le terminal :

    export PATH="$HOME/Qt/Tools/CMake/CMake.app/Contents/bin:$HOME/Qt/Tools/Ninja:$HOME/Qt/6.8.0/macos/bin:$PATH"

(On ne met dans le PATH que des dossiers d'EXÉCUTABLES — inutile d'y ajouter un dossier « lib » ni de répéter deux fois le dossier « bin ».)
Attention à entrer la bonne valeur du dossier Qt, ici 6.8.0, mais il faut remplacer par la version que vous avez réellement installée : 6.4.0, 6.4.1, 6.8.2... etc.

E - Se fabriquer une lib client UNIVERSELLE (l'étape clé de l'universel).

L'idée : le driver doit se lier à une lib client (libmariadb) qui contient à la fois du code Intel (x86_64) et du code Apple Silicon (arm64). Le problème, c'est qu'une installation de MariaDB ne fournit QUE l'architecture de votre Mac. On va donc installer MariaDB DEUX fois — une version arm64 et une version x86_64 — puis « coller » les deux libs en une seule avec l'outil lipo. Pas de panique, on déroule pas à pas.

e.1 - Installer Rosetta (la couche qui permet à un Mac Apple Silicon d'exécuter des programmes Intel). Dans le terminal :

    softwareupdate --install-rosetta --agree-to-license

e.2 - Installer Homebrew. Homebrew est un « gestionnaire de paquets » : un programme qui télécharge et installe pour vous des outils (ici MariaDB) en une seule commande, sans avoir à tout compiler à la main. Sur un Mac Apple Silicon, il s'installe tout seul dans le dossier /opt/homebrew et ne gère que l'arm64. Dans le terminal :

    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Puis on l'ajoute à votre environnement pour pouvoir l'appeler avec la simple commande « brew » :

    echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zshrc
    source ~/.zshrc

e.3 - Installer un SECOND Homebrew, en version Intel. C'est le point qui surprend : le Homebrew installé ci-dessus ne sait fabriquer que de l'arm64. Pour obtenir aussi la lib en Intel (x86_64), il faut un deuxième Homebrew, indépendant, qui tourne « en mode Intel » grâce à Rosetta. Il s'installe dans un AUTRE dossier (/usr/local), donc les deux ne se gênent pas. On lance exactement le même script d'installation, mais préfixé par « arch -x86_64 » qui le force en mode Intel :

    arch -x86_64 /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

(On n'ajoute PAS ce second Homebrew à l'environnement : on l'appellera toujours par son chemin complet /usr/local/bin/brew, précédé de « arch -x86_64 », pour ne pas le confondre avec le premier.)

e.4 - Installer MariaDB dans chacun des deux Homebrew.

    arm64 :     brew install mariadb
    x86_64 :    arch -x86_64 /usr/local/bin/brew install mariadb

IMPORTANT : installez la MÊME version de MariaDB des deux côtés (mêmes numéros). Si l'un installe 10.11.2 et l'autre 11.4.2, la fusion lipo de l'étape e.5 échouera. Au besoin, vérifiez le numéro réellement installé dans chaque dossier /opt/homebrew/Cellar/mariadb/ et /usr/local/Cellar/mariadb/.

e.5 - Fusionner les deux libs en une seule, universelle. Adaptez les numéros de version (ici 10.11.2) et le nom exact du fichier .dylib à ce qui est réellement installé chez vous :

    lipo -create \
      /opt/homebrew/Cellar/mariadb/10.11.2/lib/libmariadb.3.dylib \
      /usr/local/Cellar/mariadb/10.11.2/lib/libmariadb.3.dylib \
      -output $HOME/libmariadb-universal.dylib

e.6 - Vérifier que la lib obtenue est bien universelle :

    lipo -archs $HOME/libmariadb-universal.dylib

doit afficher « x86_64 arm64 ».

(C'est la version « à la main » de ce que fait la chaîne d'intégration de Rufus, qui, elle, recompile MariaDB Connector/C de zéro en universel. Le lipo de deux installations Homebrew est plus simple et suffit largement.)

F - Créer un sous-répertoire du dossier personnel, build-sqldrivers, et s'y déplacer :

    mkdir ~/build-sqldrivers
    cd ~/build-sqldrivers

G - CONFIGURER le driver SQL en UNIVERSEL avec qt-cmake.
ATTENTION : cette commande ne COMPILE pas encore le driver — elle ne fait que PRÉPARER la compilation (elle génère les fichiers de build). La compilation et l'installation, c'est à l'étape H.

Le point délicat : qt-cmake IGNORE l'option -DCMAKE_OSX_ARCHITECTURES et impose une seule architecture. On force donc les DEUX architectures directement au niveau du compilateur ET de l'éditeur de liens (-arch x86_64 -arch arm64), ce que la chaîne Qt ne peut plus écraser. Résultat : un binaire universel en UN SEUL build. (C'est ce qui remplace l'ancienne astuce qui consistait à éditer le fichier build.ninja à la main avec sed : devenue inutile.)

On pointe -DMySQL_LIBRARY sur la lib universelle fabriquée à l'étape E.

+++ L'option -DQT_GENERATE_SBOM=OFF n'est nécessaire qu'à partir de Qt 6.8.1 (elle évite un plantage de configuration ; sans danger sur les versions antérieures).

a - pour MariaDB :

    qt-cmake -G Ninja ~/Qt/6.8.0/Src/qtbase/src/plugins/sqldrivers \
      -DCMAKE_INSTALL_PREFIX=$HOME/Qt/6.8.0/macos \
      -DMySQL_INCLUDE_DIR="/opt/homebrew/Cellar/mariadb/10.11.2/include/mysql" \
      -DMySQL_LIBRARY="$HOME/libmariadb-universal.dylib" \
      -DQT_GENERATE_SBOM=OFF \
      -DCMAKE_OSX_ARCHITECTURES="x86_64;arm64" \
      -DCMAKE_C_FLAGS="-arch x86_64 -arch arm64" \
      -DCMAKE_CXX_FLAGS="-arch x86_64 -arch arm64" \
      -DCMAKE_SHARED_LINKER_FLAGS="-arch x86_64 -arch arm64" \
      -DCMAKE_MODULE_LINKER_FLAGS="-arch x86_64 -arch arm64"

b - pour MySQL : identique, en remplaçant seulement les chemins include/lib si vous liez la lib client de MySQL plutôt que celle de MariaDB.

Attention, là encore, à entrer la bonne valeur du dossier Qt (ici 6.8.0) et le bon numéro de version dans le chemin Cellar (ici 10.11.2).

À la fin de la CONFIGURATION (et non de la compilation), vous devez voir apparaître en général les lignes suivantes :

    -- Configuration summary has been written to /Users/xxx/build-sqldrivers/config.summary
    -- Configuring done (6.5s)
    -- Generating done (0.0s)
    -- Build files have been written to: /Users/xxx/build-sqldrivers

H - COMPILER, COPIER À LA MAIN, puis VÉRIFIER.

    cmake --build .        (attention à l'espace entre build et le point)

ATTENTION : sous macOS, « cmake --install . » ne fonctionne pas pour ce driver (la chaîne sqldrivers de Qt ne sait pas s'installer toute seule). Il faut copier le fichier produit À LA MAIN, à chaque fois. Le driver compilé se trouve ici :

    ~/build-sqldrivers/plugins/sqldrivers/libqsqlmysql.dylib

Copiez-le dans le dossier des plugins de votre Qt :

    cp ~/build-sqldrivers/plugins/sqldrivers/libqsqlmysql.dylib ~/Qt/6.8.0/macos/plugins/sqldrivers/

Vérifier qu'il est bien UNIVERSEL :

    lipo -archs ~/Qt/6.8.0/macos/plugins/sqldrivers/libqsqlmysql.dylib

doit afficher « x86_64 arm64 ». Si une seule architecture apparaît, c'est que les options -arch de l'étape G n'ont pas été prises : reconfigurez dans un dossier build VIDE (cmake garde en cache l'ancienne configuration).

I - Supprimer les libs inutiles dans ~/Qt/6.8.0/macos/plugins/sqldrivers :

    rm -f ~/Qt/6.8.0/macos/plugins/sqldrivers/libqsqlite.*
    rm -f ~/Qt/6.8.0/macos/plugins/sqldrivers/libqsqlodbc.*
    rm -f ~/Qt/6.8.0/macos/plugins/sqldrivers/libqsqlpsql.*

Voilà, c'était presque simple.
