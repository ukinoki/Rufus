
6. Installer Qt6 et construire le driver MySQL pour MariaDB ou MySQL 8.0 sous macOS Intel x64 - build MySQL driver QT6 MacOs intel x64

Comme d'habitude, tout cela est très mal expliqué dans la documentation de Qt, les gens de Qt considérant que vous êtes le petit prince de l'informatique et que vous saurez pallier les insuffisances de leurs explications.
Et que si, pour votre malheur, vous n'êtes pas ce petit prince, vous n'avez qu'à abandonner, parce que vous êtes trop stupide et l'informatique n'est pas faite pour vous.

Bon, ce coup de gueule posé, la compilation du driver n'est pas si complexe. Il vous faut installer Qt 6.3 ou supérieur (et même Qt 6.8 minimum si vous êtes sous macOS Tahoe) et les SOURCES du logiciel par le biais du logiciel d'installation de Qt, MaintenanceTool. Donc, modifiez ou faites une installation neuve en cochant la case « Sources » du logiciel d'installation, comme indiqué dans la capture d'écran ci-contre.

Il vous faut aussi installer CMake et Ninja en cochant les cases correspondantes (mais elles le sont normalement par défaut).

On est loin d'avoir fini...

A - Télécharger Xcode sur l'App Store et l'installer.

B - Indiquer au système le chemin vers les outils dont il aura besoin pour compiler le driver.
Pour cela, on ajoute les dossiers contenant qt-cmake, cmake et ninja à la variable PATH, en entrant dans le terminal :

    export PATH="$HOME/Qt/Tools/CMake/CMake.app/Contents/bin:$HOME/Qt/Tools/Ninja:$HOME/Qt/6.10.2/macos/bin:$PATH"

(On ne met dans le PATH que des dossiers d'EXÉCUTABLES — inutile d'y ajouter un dossier « lib ».)
Attention à entrer la bonne valeur du dossier Qt, ici 6.10.2, mais il faut remplacer par la version que vous avez réellement installée : 6.4.0, 6.4.1, 6.8.2... etc.

C - Créer un sous-répertoire du dossier personnel, build-sqldrivers, et s'y déplacer :

    mkdir ~/build-sqldrivers
    cd ~/build-sqldrivers

D - CONFIGURER le driver SQL avec qt-cmake.
ATTENTION : cette commande ne COMPILE pas encore le driver — elle ne fait que PRÉPARER la compilation (elle génère les fichiers de build). La compilation et l'installation, c'est aux étapes E et F.

a - pour MySQL :

    qt-cmake -G Ninja ~/Qt/6.10.2/Src/qtbase/src/plugins/sqldrivers -DCMAKE_INSTALL_PREFIX=$HOME/Qt/6.10.2/macos -DCMAKE_OSX_ARCHITECTURES="x86_64" -DQT_GENERATE_SBOM=OFF -DMySQL_INCLUDE_DIR="/usr/local/mysql/include" -DMySQL_LIBRARY="/usr/local/mysql/lib/libmysqlclient.dylib"

b - pour MariaDB :

    qt-cmake -G Ninja ~/Qt/6.10.2/Src/qtbase/src/plugins/sqldrivers -DCMAKE_INSTALL_PREFIX=$HOME/Qt/6.10.2/macos -DCMAKE_OSX_ARCHITECTURES="x86_64" -DQT_GENERATE_SBOM=OFF -DMySQL_INCLUDE_DIR="/usr/local/Cellar/mariadb/11.3.2/include/mysql" -DMySQL_LIBRARY="/usr/local/Cellar/mariadb/11.3.2/lib/libmysqlclient.dylib"

Attention, là encore, à entrer la bonne valeur du dossier Qt (ici 6.10.2) et, pour MariaDB, le bon numéro de version dans le chemin Cellar (ici 11.3.2).

À la fin de la configuration, vous devez voir apparaître en général les lignes suivantes (mais pas forcément, selon le fichier source du driver) :

    -- Configuration summary has been written to /Users/xxx/build-sqldrivers/config.summary
    -- Configuring done (4.6s)
    -- Generating done (0.3s)
    -- Build files have been written to: /Users/xxx/build-sqldrivers

E - COMPILER le driver.
C'est maintenant que la compilation a lieu réellement :

    cmake --build .

F - INSTALLER le driver dans Qt :

    cmake --install .

Le driver (libqsqlmysql.dylib) est alors copié dans le dossier des plugins de votre Qt :

    ~/Qt/6.10.2/macos/plugins/sqldrivers/libqsqlmysql.dylib

Pour vérifier qu'il s'agit bien d'un binaire Intel x64 :

    lipo -archs ~/Qt/6.10.2/macos/plugins/sqldrivers/libqsqlmysql.dylib

doit afficher « x86_64 ».

---

Un problème se présente parfois à partir de la version 6.8.1 de Qt : à l'étape D, la configuration peut planter avec un message cabalistique du genre :

    CMake Error ...etc...  no SBOM project name MySQL

C'est pour cela qu'on a ajouté ci-dessus l'option -DQT_GENERATE_SBOM=OFF à la commande qt-cmake : elle désactive la génération du « SBOM » (la nomenclature logicielle) et évite tout simplement le bug.

Si vous aviez oublié cette option et que vous tombez sur l'erreur, deux solutions :
- la plus simple : relancez la commande qt-cmake en y ajoutant -DQT_GENERATE_SBOM=OFF (comme ci-dessus) ;
- ou, à l'ancienne, désactivez le SBOM sur le module des sources, puis relancez qt-cmake :

    ~/Qt/6.10.2/macos/bin/qt-configure-module ~/Qt/6.10.2/Src/qtbase/src/plugins/sqldrivers -no-sbom
