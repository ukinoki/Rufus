	→ vérification de la présence d'un serveur MySQL
		→ si OK
			→ recueil de la version du serveur
				→ si version MySQL < 8.0.14 ou serveur MariaDB
					→ message - "IMPORTANT
								Rufus stocke les données de vos patients dans une base de donnée stockée
								 	→ sur ce poste
								 	→ ou un autre poste de votre réseau
								 	→ ou sur un poste serveur distant sur internet
								Cette base patients est gérée par un autre programme, le serveur de base de données MySQL, indispensable au fonctionnement de Rufus
								L'installation de MySQL est effectuée par Rufus lors de son premier lancement
								Si vous ne comptez pas héberger votre base patients sur ce poste, ne  tenez pas compte de ce message
								
								Cette nouvelle version de Rufus embarque une sécurisation des mots de passe bien plus forte que les précédentes
								mais nécessite un serveur MySL dont la version doit être supérieure à 8.0.14
									→ votre poste héberge déjà un serveur MySQL/MariaDB
								 	Cependant, 	la version du serveur MySQL hébergée par votre poste est trop ancienne et n'est pas compatible avec cette version de Rufus
								 			/	le serveur hébergé sur votre poste est un serveur MariaDB et n'est pas compatible avec cette version de Rufus
								 A son premier lancement, Rufus vous proposera de mettre à jour le serveur
								 Cette mise à jour entraînera une perte de vos données et nécessite donc une sauvegarde.
								 	Si votre base de données présente sur ce poste est une base patients Rufus,
								 		Rufus pourra, avant de mettre à jour le serveur, sauvegarder cette base patients
								 		et la restaurer après la mise à jour
								 	Si votre base de données contient d'autres données qui ne sont pas une base patients Rufus,
								 		il est fortement conseillé de faire une sauvegarde de vos données
								 		qui seront sinon irrémédiablement perdues
								 Voulez-vous continuer à installer Rufus?
						→ 2 boutons : 1. Annuler, je ferais ça à un autre moment   2. OK, continuer
					→ Ce message est affiché dans une des 5 langues implémentées dans Rufus
						pour savoir quelle langue utiliser, on utilise la variable stockée ans Rufus.ini s'il y en a un, sinon le QLocqle().
						Dans le doute, on utilise le français

II LANCEMENT DE RUFUS
	6 paramètres :
	1. Présence ou non d’un rufus valide (avec au moins un mode de connexion paramétré)
		4 situations
			a. pas de rufus.ini ou rufus.ini invalide (pas de mode de connexion paramétré)
			b. rufus.ini et monoposte
			c. rufus.ini et réseau local
			d. rufus.ini et accès distant
	2. présence d’un .dbkey
	3. présence d’un serveur
	4. s'il y a un serveur, présence d’une base Rufus sur ce serveur
	5. s'il y a un serveur, est-il conforme au mini de la version SQL
	6. présence de clés SSL valides pour l'accès distant

	La séquence se déroule à chaque lancement de Rufus

1. pas de rufus.ini ou rufus.ini invalide sans mode de connexion paramétré
	→ voir s'il y a un rufus.ini de sauvegarde dans le dossier .rufus
	→ si oui, vérifier s'il est valide,
		→ si oui
			→ message "absence de fichier de configuration Rufus.ini ou fichier Rufus.ini corrompu, voulez vous restaurer la copie de sauvegarde?""
				→ bouton annuler → fermeture du programme
				→ bouton restaurer la copie
				→ bouton revoir les parametres de connexion → RecupererDemarrage()
	→ si non
		→ message " absence de fichier de configuration Rufus.ini ou fichier Rufus.ini corrompu"
				→ bouton annuler → fermeture du programme
				→ bouton revoir les parametres de connexion → RecupererDemarrage()
				
2. rufus.ini paramétré correctement avec un ou plusieurs modes de connexion
